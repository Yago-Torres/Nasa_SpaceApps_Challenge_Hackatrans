# Changelog — human-verified behavior only

## Unreleased

- ABB-29 test suite (no user-visible behavior change): a main-journey end-to-end test drives the public API from case creation through NASA POWER, reviewed evidence, a concluded hypothesis, the three rotation alternatives, external review and the versioned report, with SYNTHETIC fixtures and pinned failure cases; a contract check compares the backend OpenAPI document with the frontend types in CI; a manual smoke test for the real NASA POWER, Crossref and OpenAlex services (`make smoke-real`) is provided but has not been run yet. CI publishes `openapi.json` as an artifact. See `docs/operations/E2E_AND_CONTRACTS.md`.

- ABB-25 collaboration between communities: case owners invite people by e-mail with a role (Editor, Reviewer, Viewer), a note and an expiry, and can revoke pending invitations or existing access; invitees accept or decline on the Collaboration page after signing in with that address (no e-mail is sent and addresses are not verified, which the form says). Every member, viewers included, can post plain-text comments and one-level replies in a new Discussion tab; authors edit with the earlier text kept as visible history, deletions leave a signed tombstone, and owners can moderate. The same tab shows a read-only activity feed of who did what, when, on which record and with which recorded evidence. Owners can create a revocable, expiring read-only share link for people without an account after choosing each section and confirming consent; the public view never includes exact field locations, e-mails, the member list, observations or history. Deleting an account now also revokes pending invitations to its e-mail. Fixes an intermittent ordering of disagreement decisions (ABB-15) when the clock steps back.

- ABB-24 rotation comparator: the Rotations screen replaces the illustrative demo and sends the farmer's recorded crop history, local calendar, water/market/equipment constraints and ordinal priorities to the backend comparison/scenario endpoints. It displays returned strategies, trade-offs, missing inputs and review limitations; priority changes recompute through the backend. Optional hypothetical climate flags (dry spring, wet autumn, hot summer, cold winter) and a priority-swap check also run on the backend. A failed recompute keeps the previous result but marks it as not reflecting the latest changes. Outputs remain descriptive MODEL_SCENARIO results with no yield, savings or verified impact claims.

- ABB-22 web timeline (in review): authenticated case workspaces gain a shared tab route and a Timeline tab that renders the real ABB-10 OBSERVED, FARMER_REPORTED, HYPOTHESIS and MISSING_DATA layers without interpolating gaps. Findings are keyboard-selectable, have a table alternative and open the backend provenance, QA and limitations; linked observation evidence resolves to its anomaly event. Owners and editors can add rival hypotheses and reviewers can evaluate them without scores or probabilities. Catalogue and upstream failures remain explicit and never substitute demo values.

- ABB-23 case evidence: a new Evidence tab in each case shows the studies kept for the case as provenance labels (claim, paper, DOI as registered and its Crossref status, what was read, study design and conditions, outcome as stated, limitations and warnings). Only claims a reviewer accepted after reading the full text carry the reviewed-literature symbol; every other claim is marked "Not reviewed" with an icon and text, counted, and filterable. Owners and editors can search OpenAlex and add a study, which is registered by its DOI and saved as not reviewed. Each claim shows its review history and can be checked for transferability to the case (no score). Disagreements between studies show as candidates with the recorded differences and every reviewer note. The evidence graph runs from original records to conclusions with legend symbols, a text alternative and folded unlinked NASA values; opening a conclusion traces it to the observations, farmer reports and DOIs it rests on, with unreviewed literature and what blocks its acceptance. The global Evidence page now points to this tab instead of saying review is not built.

- ABB-28 security, privacy and data operations: `GET /api/v1/account/export` lets a signed-in user download their own profile, every case they are a member of (with the same role-aware coordinate redaction `/cases` already applies) and their own session metadata (never a token). `POST /api/v1/account/delete` (current password required again, same 5-attempt lockout as sign-in) permanently erases every case the account owns, revokes its access to every case owned by someone else, revokes every session, and anonymises the account's e-mail/display name and disables its login — without deleting the account row outright, so another member's reviewed evidence on a case they do not own never loses its author/reviewer reference (ADR-0005). A new maintenance function purges session rows 30 days past expiry/revocation (not yet scheduled). Security/privacy audit of logging, CORS and existing rate limiting found no coordinate/token/password logging and no permissive CORS; one real gap was found and documented rather than fixed (out of this change's file scope): the NASA POWER on-disk response cache stores exact queried coordinates in plaintext, bypassing case-level privacy redaction. New `docs/operations/LEGAL_AND_DATA_POLICY.md` (legal notice, agronomic disclaimer, third-party data terms for NASA POWER/OpenAlex/Crossref, and the full data minimisation/retention/export/deletion/consent policy).

- ABB-21 / ABB-06 (web): sign in, create an account and sign out in the Cases screen (EN/ES). Cases are saved to the server under your account instead of this browser: the incident wizard creates the case once it has a name, a location and the incident year, then autosaves each change. If someone else saved first, you choose between loading their version and saving yours over it. The cases list shows status, your role and the location as reviewers see it; reviewers and viewers open cases read-only and only ever receive the rounded cell, the region name or nothing, unless the owner consented. The sign-in token stays in the open tab only. Cases saved in the browser by the earlier development version are not imported and can be deleted from the Cases screen. - ABB-10: case-bound NASA POWER evidence (`POST /api/v1/cases/{id}/observations/nasa-power`, `GET …/observations`) using the field's stored location server-side, with source manifest, monthly observations, anomalies and QC flags; idempotent/versioned re-ingestion; nothing stored on upstream failure (502). Forensic timeline `GET /api/v1/cases/{id}/timeline` with OBSERVED, FARMER_REPORTED, HYPOTHESIS and MISSING_DATA layers, provenance, limitations and a documented descriptive severity rule. Rival hypotheses `/api/v1/cases/{id}/hypotheses` (CRUD, evaluation as COMPATIBLE / CONTRADICTED / NOT_EVALUABLE, evidence links validated within the case, six OPEN templates with verification questions; no probabilities). Coordinates are withheld from reviewers and viewers.
- ABB-19 Uncertainty Hunter (API): `GET /api/v1/cases/{id}/uncertainty` lists, per case, the missing or unreliable data (timeline gaps, missing evidence and verification questions of hypotheses, unreviewed claims and unknown applicability; with a farm profile POSTed, also the ABB-11 profile issues, ABB-17 checks and ABB-18 ordering) and turns them into concrete local questions: why each matters, what to measure (with units) and which recorded hypotheses or decisions could change. There is never a value-of-information score; when there is no basis to prioritise, the response says so. Members record local answers (FARMER_REPORTED; corrections supersede, never overwrite), another member reviews them, and questions can be dismissed or reopened with full history. Answers can be cited as hypothesis evidence. API only; no UI yet.
- ABB-16 evidence graph: `GET /api/v1/cases/{id}/evidence-graph` shows each case's observed NASA POWER values, farmer reports, fields, papers, claims, rival hypotheses, conclusions and missing data as typed nodes and edges, with provenance (never coordinates), review state and authorship. Derived links are generated from the records; contradictions confirmed in ABB-15 appear as CONTRADICTS edges. Case members can write conclusions that must cite supporting evidence and state limitations; `GET …/evidence-graph/trace/{node}` follows every conclusion back to its original evidence. Conclusions and manual links are reviewed by a member who did not write them; acceptance requires a complete trace, reviewed literature and evaluated hypotheses. Links to nonexistent or other-case records are rejected, and referenced hypotheses, claims and fields cannot be deleted. No scores or probabilities. API only; no UI yet (ABB-23). Fixed: a case edit could fail with a 500 when the server clock stepped back.
- ABB-15 contradictions and applicability: claims gain structured comparability fields entered by people (intervention, comparator, outcome variable, direction as stated) and structured study conditions (water regime, USDA texture classes, pH range, countries/scope, Köppen–Geiger classes). `GET /api/v1/cases/{id}/claims/disagreements` lists candidate disagreements (same intervention and outcome, opposed stated directions) with both references and recorded differences. Reviewers record CONFIRMED_CONTRADICTION (only when both claims are reviewed), NOT_COMPARABLE or INCONCLUSIVE with a note; a decision stops applying when either claim changes. `POST /api/v1/cases/{id}/claims/{claim_id}/applicability` returns per-dimension transferability notes (match / partial / mismatch / unknown, each with a reason); missing data stays unknown and no applicability score is produced. API only; no UI yet.
- ABB-14 evidence claims: register papers by DOI/OpenAlex ID (metadata fetched from OpenAlex and checked in Crossref, never taken from the client) and record case-scoped structured claims (study design, context, outcome/units/uncertainty as stated, attributed short quotation, licence and access basis). Human review workflow (accepted / rejected / changes requested) with an append-only history of who reviewed, when and which source they consulted; only accepted claims are shown as reviewed literature, and authors cannot review their own claims. Optional import of the three unverified pilot cards as pending claims. API only; no UI yet.
- ABB-05/ABB-06 accounts and private cases: sign-up, sign-in and sign-out under `/api/v1/auth`; case management under `/api/v1/cases`. Cases are private by default. Owners share them by role (editor, reviewer, viewer) and can revoke access immediately. Reviewers and viewers never receive a parcel's exact location unless the owner consents. Every edit is versioned with author, time and previous values. Workflow: draft → investigating → reviewed → published (publishing does not make a case public). Requires PostgreSQL (`DATABASE_URL`); without it these routes answer 503. The web app still uses development browser storage until its HTTP adapter is built.
- ABB-07/ABB-08: `GET /api/climate` now returns typed provenance (`SourceManifest` 1.0: endpoint, query, UTC `retrieved_at`, SHA-256, POWER API version, ½°×⅝° spatial and daily temporal resolution, limitations), cache status and POWER header metadata. Requests retry boundedly on timeouts/429/5xx and fail with generic 502 messages, never simulated values. Monthly anomalies carry per-month quality flags (complete/partial/missing with day counts), reference-year coverage and a method description; fill values (-999) and partial months are never aggregated; short reference windows are labelled as not climatological normals. Method: `docs/science/CLIMATE_ANOMALIES.md`.
- ABB-18: new stateless `POST /api/v1/rotations/scenarios` and `POST /api/v1/rotations/sensitivity`. A what-if changes the farmer's ordinal priorities and/or water availability and reruns the unchanged ABB-17 comparison, adding each strategy's calendar exposure to labelled climate scenarios: observed historical episodes passed in from `/api/climate` (flagged with user-chosen thresholds) and hypothetical month flags; neither is a forecast. Strategies are ordered by declared constraints and then by the farmer's ranks one criterion at a time, with every step, tie and trade-off explained; there are no weights or scores. Sensitivity reports which criteria, strategies and positions change after a priority swap, a water change or a scenario change, and why. Responses carry a canonical input SHA-256; `verified_impact` stays null.
- ABB-17: new stateless `POST /api/v1/rotations/compare`. From a farm profile it lists the current rotation (derived from crop history) first, followed by up to three rule-generated alternatives (minimal change, family diversification, calendar cover) screened against the farmer's declared calendar windows, excluded crops, markets and water regime. Impossible calendar sequences are rejected and crops without a declared window are not evaluated. The comparison is descriptive, with qualitative possible benefits, risks and review conditions; no yield, water or income figure or score is produced and `verified_impact` stays null.
- ABB-11: new `GET /api/v1/crop-catalog` (taxonomy only, pending review) and stateless `POST /api/v1/farm-profiles/assess`, which validates farmer soil (local measurement vs regional estimate), crop history, local calendar, constraints and ordinal priorities, and lists missing data with the analysis each gap limits. No agronomic outcome is computed.
- ABB-13: `/api/literature` now verifies each DOI against Crossref, normalizes authors/venue/licence/retrieval time, removes duplicates and labels every result `LITERATURE_METADATA` / `BIBLIOGRAPHIC_MATCH_ONLY` with a DOI status. Fixed: an upstream error could expose `OPENALEX_API_KEY` in the 502 response detail.

- ABB-26 case report (in review): `POST /api/v1/cases/{id}/reports` stores an immutable, numbered report version built by the server from the case (context, NASA source manifests with retrieval/content checksums, monthly anomalies, rival hypotheses, literature claims with DOIs and review class, human conclusions, rule-based rotation strategies when a farm profile is supplied, collaboration counts, limitations). Each version records its date, the case version, one hash over all sources, the hashes of its Markdown/HTML/JSON forms and the records added, removed or changed since the previous version; a database trigger makes stored content write-once and `GET …/verify` recomputes the hashes. Downloads (Markdown, HTML, JSON) are available in a new case "Report" tab. Exports never contain exact coordinates, the shared location cell, incident notes, e-mails, member names or comment text. PDF is not generated (browser print of the HTML). New migration `d5f3a8b21c64`. See `docs/science/CASE_REPORT.md`.

- ABB-26 PDF export (in review): case report versions now also store a PDF (ReportLab, ADR-0007) built from the same content as the Markdown/HTML, downloadable from the Report tab and covered by `verify`. Versions created before this change have no PDF. New dependency `reportlab` (plus `pillow`, `charset-normalizer`), migration `e8a4c1d7f905`.
